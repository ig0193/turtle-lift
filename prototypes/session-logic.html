PROTOTYPE — workout session state model

The question: does the session model hold up when driven end to end, given that nothing derived is stored? Streak, personal bests, the “trained” ticks and the session title are all recomputed on read. That is elegant on paper. This demo pushes it through the cases that are hard to reason about: four load types, an abandoned session, a backdated workout that rewrites an earlier one’s history, and an assisted lift where a smaller number is the record.

Throwaway. In-memory only — refresh wipes everything. The logic lives in one pure module at the top of the source and is meant to be lifted into Dart; the page is a shell.
